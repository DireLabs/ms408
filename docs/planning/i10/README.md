# i10 — Is the manuscript *data* rather than *language*? (symbols-as-values)

**Inherits** all locks L1–L37; the standing clean-context refutation rule; the firewall
(L3); the harness rule (L4); **L7 absolute** (no decipherment/meaning/value claim without an
independent anchor); A/B + hand stratification (L8); consume-only external data until Tim

## The question

Does Voynichese behave like a **non-glottographic quantitative register** — signs carrying
*values* (numbers, magnitudes, tallies, coordinates) rather than phonemes — the grounded,
realistic version of the "each symbol carries a value" idea? Precedent: khipu (decoded
base-10 positional), Cistercian numerals (period-contemporary place-value), gematria.

## Why this is worth a look (and grounded, not hand-waving)

Exploratory reads on the ZL transliteration (to be formalised by E27) already show the data
supports concrete tests:
- **~39 raw EVA glyphs, but ~15 carry nearly all the mass** (o,e,h,y,a,c,d,i,k,l,… ; the rest
  are rare) → a small effective symbol set, in the size range of a numeral/syllabary, not a
  large alphabet.
- **Strong positional glyph grammar** — distinct word-initial vs word-final glyph sets — i.e.
  a real "slot" structure to test as digit-slots vs syllable-slots.
- **A ready-made ordinal target:** 12 zodiac pages carry **angular-position-tagged labels**
  (`<!09:00>…`, `<!10:00>…`, `<!00:00>…`) plus 84 circular + 142 radial loci. The
  transliteration records **where each label sits around the ring**, so we can test whether
  label *content* varies with angular position — exactly what a degree/date/count would.

And the whole envelope is **consistent with** a register: low h₂ (small symbol set), weak
word-syntax (data has none), block-scale ΔI (tabular/columnar), dense ED1 families
(place-value families), cipher-of-prose excluded (a register is not prose). See FRAMEWORKS §2.

## The load-bearing discipline (read before proposing any experiment)

**Distributional characterisation CANNOT settle this.** i09 showed our own positional/
type-lexicon generator reproduces the VMS distributional signature *without* being numbers —
so glyph-inventory and digit-slot tests will, at best, say "consistent with a register,"
which is exactly where FRAMEWORKS §5 already leaves us. Matching numeral-register statistics
is **necessary, not sufficient** (Rugg 2004, Timm–Schinner 2019 match VMS stats with *no*
meaning). Therefore:

1. **Anchor-first.** The iteration lives or dies on a **decipherment-free arithmetic/ordinal
   anchor** — the one thing that separates "consistent with a register" from "is a register."
   Run the killable anchor test EARLY (like E12/E20), before investing in characterisation.
2. The strongest available anchor is **not** generic summation (the VMS has no figure-columns)
   but **ordinal/periodic structure in the angular-tagged circular diagrams** (zodiac rings,
   radial sequences): if labels are values, their content should track angular position
   monotonically or periodically beyond a matched null.
3. If the anchor is **null** across the astronomical folios, the register hypothesis stays at
   grade D and the iteration **closes with a clean negative** (a real result — it removes a
   revived hypothesis, like i06 did for ciphers). If it **signals**, *then* invest in
   characterisation + numeral-register control corpora to build the graded case.
4. **L7 is absolute.** No output is a value, a number, a date, or a reading. A positive is a
   *statistical* ordinal/arithmetic regularity, refutation-passed, never a decoding.
